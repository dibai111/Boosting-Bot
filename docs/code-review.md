## 整體判斷

專案的分層基礎合理：前端已區分畫面、流程及 IPC；後端已區分命令、runtime、Bot actor、配對協調器及本機儲存。函式命名大致能表達用途，Rust 的命名與模組安排尤其一致。主要維護成本來自大型畫面元件、CSS 多次覆寫，以及缺少統一的前端格式設定。

本次檢查涵蓋自行維護的 Rust、TypeScript、Svelte、CSS、入口與建置設定。第三方依賴、鎖定檔、二進位素材及 Tauri 產生的 schema 不視為手寫程式碼；JSON 不加入語法不支援的註解。

## 尚待改善

1. **`App.svelte` 責任仍偏多。** 導覽、帳號表單、設定、工作階段及對話框仍由同一元件協調。建議下一步以頁面和對話框拆分，讓 controller 持有共用狀態，避免拆分後再產生兩份狀態。此次已先移除重複包裝並修正反應依賴。
2. **全域 CSS 仍有歷史覆寫。** 帳號卡片、側欄與配對面板在不同位置重設相同屬性，部分卡片背景備援已被最後的 SVG 規則蓋過。可逐區移回元件或按責任拆檔；需要以桌面實際畫面比對淺色、深色、縮放和減少動態效果。此次未全面重排層疊順序。
3. **停止 Bot 的等待不是完整的五秒上限。** `bot_runtime/engine.rs` 先對完成通知等待五秒，之後仍等待 `thread.join()`；若連線執行緒無法退出，停止操作可能持續等待。應另設計連線 runtime 的可取消退出途徑並做故障注入驗證；單純放棄 join 會留下仍存活的 Bot 執行緒。
4. **工作模式的啟動／停止存在交錯空間。** `runtime/nick.rs` 與 `runtime/matchmaking.rs` 的模式切換及實際命令分多個 await 完成。若並行呼叫啟停，可能出現模式已退出而啟動命令尚未送完的時序；需要交易式生命週期鎖或 generation token 與並行測試。這是靜態檢查指出的待驗證問題，尚未透過實際連線重現。

## 驗證範圍

本次增加非同步監聽清理、Nick 候選期限、快捷鍵無效輸入與配對遲到確認的回歸測試。最終結果如下：

- `pnpm format:check`、`git diff --check` 通過。
- `pnpm check`：0 errors、0 warnings。
- `pnpm test`：11 個測試通過。
- `cargo test --workspace --lib`：主程式 61 個、本機儲存 3 個測試通過。
- `pnpm lint:rust`：全部 targets 通過 `-D warnings`。
- `pnpm build` 成功；`skinview3d` 分塊約 519 kB，仍有超過 500 kB 的建置提示。該功能已使用動態載入，進一步縮減需分析 3D 依賴。

Node 的 TypeScript 型別移除功能仍輸出 experimental 提示；Rust 測試連結器輸出建立 `.lib`／`.exp` 的訊息。兩者未造成測試失敗。

這些檢查不包含真實 Microsoft 登入、Hypixel 連線、完整 Tauri 安裝包及所有桌面互動的端到端驗證。程式碼檢查無法證明所有執行時情況都沒有錯誤。
